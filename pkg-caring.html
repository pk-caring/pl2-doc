케어링 기능 계층 — 플랫폼 위에 얹은 북치기. caring_m 에만 있다

실물 대응 — 북 ×1 · 손에 쥐는 북채 ×2 · 음원을 트는 폰 1대(오디오 마스터)

플랫폼(pl2_* · pl_*)은 팔을 움직이는 법을 안다. 케어링 계층은 그 팔로 무엇을 할지를 안다 — 지금은 북치기 하나다. 저장소 셋으로 갈라져 있고, 셋 다 src/ 밑에 vcstool 로 조립되는 점은 다른 도메인과 똑같다.

중요한 것은 의존이 한 방향이라는 점이다. 케어링은 플랫폼을 부르지만, 플랫폼은 케어링을 절대 부르지 않는다. 플랫폼 저장소는 케어링 없는 형제 워크스페이스(pk-caring/pl_2m)와 공유하는 물건이라, 역방향 import 하나가 그쪽에서 허공을 가리키기 때문이다. 이 규칙은 문서가 아니라 게이트다 — 워크스페이스 테스트가 매번 검사한다.

03

핵심

#
의존은 한 방향케어링 → 플랫폼만. 플랫폼 저장소는 pl_2m 과 공유하므로 역방향 import 는 그쪽에서 허공을 가리킨다 — tests/test_caring_boundary.py 가 매 실행 검사한다
특권 없는 합류북치기가 팔을 얻는 방법은 다른 intent 소스와 같다: command_intent_raw 로 들어가 움직임 필터와 안전 게이트를 지난다. 조립에서는 components.yaml 의 percussion 한 줄일 뿐이다
표면은 서비스스튜디오는 여러 클라이언트 중 하나다. ros2 service call 만으로 전부 조작된다 — 상태를 바꾸는 것은 서비스뿐이고 status 는 관측 전용
교시가 아니라 유도북의 네 숫자(지름 · 높이 · 거리 · 기울기)와 파지 사실에서 타격 자세를 IK 로 푼다. 백스윙은 손목 관절 하나(j6)를 되감아 만들어, 두 자세가 숫자 하나만 다르다
못 치면 탈락적재 시점에 전 세그먼트가 필터 캡 안임을 검증하고, 못 넣는 타격은 빼고 보고한다 — 늦게 치는 것보다 안 치는 게 정직하다
지연은 상수 하나전 타격이 같은 스윙이라 스피커·서보의 고정 지연이 상수로 붕괴한다. 그래서 귀로 맞추는 SetSync 오프셋 슬라이더 하나로 충분하다
죽으면 침묵시퀀서와 lease keeper 가 한 launch 트리다. 죽이면 스트림이 멎고 lease 는 게이트에서 스스로 소멸한다 — 침묵으로 반납된다

시연이 밟는 순서

#
1연주 노드 켜기 — 설정 서랍에서 percussion 컴포넌트를 launch 트리째 스폰
2연주 준비 자세 → 좌·우 그리퍼를 열고 닫아 사람이 북채를 쥐여 준다
3곡 업로드 — 서버가 랩 CLI 로 분석해 악보를 굽는다(수 초, 캐시). 곡의 정체는 파일 내용(content hash)
4곡 선택 — 고르는 순간 리그의 현재 상태로 다시 굽는다. 자세를 다시 가르쳤어도 랩을 다시 돌 필요가 없다
5재생 — 폰이 Web Audio 로 음원을 틀고 clock 핸드셰이크로 서버 시계에 앵커한다(불확실성 30 ms 초과면 거부). 로봇이 카운트인을 스틱 클릭으로 세고 오디오가 뒤따라 시작한다
6싱크 오프셋 — ±500 ms 라이브 슬라이더로 귀에 맞춘다. 블루투스 스피커는 +100~300 ms 급

실전 코드 — 경계는 게이트다

#

케어링이 플랫폼을 부르는 것은 정상이고, 반대는 빌드를 깬다. 언급이 아니라 import 로 판정한다 — components.yaml 이 percussion 을 이름으로 적는 것은 조립 어휘이지 의존이 아니기 때문이다.

# tests/test_caring_boundary.py
_IMPORT = re.compile(r"^\s*(?:import|from)\s+(cr_[a-z_]+)", re.M)

def test_platform_never_imports_the_caring_layer():
    offenders = []
    for path in _py_files_outside_cr():
        for hit in _IMPORT.findall(path.read_text()):
            offenders.append(f"{path}: imports {hit}")
    assert not offenders, (
        "the platform depends on the caring layer — "
        "the dependency only points the other way:\n" + "\n".join(offenders))

예외는 하나, robot/launch/sim_percussion.launch.py 다. 부모의 robot/ 밑에 살지만 케어링 스택을 세우려고 존재하는 파일이라 애초에 플랫폼 부모로 옮겨갈 수 없다 — 게이트가 지키는 것은 플랫폼 파일의 이식성이지 파일의 위치가 아니다.
