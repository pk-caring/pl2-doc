## Project

`pl2-doc` — the static site that explains the **Caring M** workspace (`pk-caring/caring_m`) to
someone seeing it for the first time: a folder tree, a layer map, and one page per package.
Published by GitHub Pages from `main` at <https://pk-caring.github.io/pl2-doc/>, so a merge
here is a deploy.

The pages are generated artefacts in spirit — the authority for every claim on them is the
workspace itself (`caring_m` and each domain repo's `README.md` and `wiki/`). Never invent a
fact here; read it there first. The site is self-contained: mermaid and highlight.js are
vendored under `vendor/`, code highlighting is baked in at edit time rather than run in the
browser, and no page may reach for a CDN.

## Collaboration rules

Three gates, and no change is small enough to skip them.

- **Always work on a branch.** `main` is never committed to directly, not for a one-line
  fix. Cut the branch from an up-to-date `main`:

  ```bash
  git fetch origin && git switch -c <category>/<subject> origin/main
  ```

- **Branch names are English, category first.** `<category>/<subject>`, where `<category>`
  is one of `feat`, `fix`, `chore`, `refactor` — the same word the commit subject starts
  with. Lower-case, hyphen-separated, no Korean: `feat/ik-teleop-rest-pose`,
  `fix/stick-tip-placement`, `chore/re-pin-workspace`, `refactor/requirements-ssot`.

- **Always open a PR.** Push the branch and open a pull request against `main`. Nothing
  reaches `main` any other way — no direct push, no local merge:

  ```bash
  git push -u origin <branch> && gh pr create --base main
  ```

  The body says what changed and how it was verified; anything that needs the real robot is
  listed as pending, not claimed as done.

- **Always squash merge.** A PR lands as exactly one commit on `main`:

  ```bash
  gh pr merge --squash --delete-branch
  ```

  No merge commits, no rebase merges, and never the branch's own commits on `main`. Squash
  does not mark the branch merged locally, so clean up with `git branch -D <branch>`.

- **This repo is a deploy, not a draft.** Merging to `main` publishes the site. Check a page
  in a browser before opening the PR — a local `python3 -m http.server` is enough — and say
  in the PR what you checked.

- **Commits** — English subject and body, starting with the same category as the branch
  (`feat:`, `fix:`, `chore:`, `refactor:`), and no AI or agent attribution of any kind (no
  `Co-Authored-By`, no "generated by").
