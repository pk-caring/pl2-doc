02

통신 종류

#
전송싣는 것알아둘 것
DDS (ROS 2 토픽)관절 상태 · 명령(intent) · 리더 상태ROS 2 의 기본 통신이다. 노드끼리 서로를 자동으로 찾는다. 각 토픽의 QoS(신뢰성·큐 깊이)는 모듈 계약이 선언하고, 코드에 상수로 적지 않는다.
ZMQ카메라 JPEG 프레임카메라만 ROS 밖으로 돌린 이유: 영상은 크고, 필요한 건 항상 최신 한 장이다. PUB/SUB + 최신-프레임 옵션이 이 요구에 맞는다. 구독자는 몇 개든 붙을 수 있다.
CAN-FD모터 명령 · 상태차량·로봇에서 쓰는 장치 버스다. 팔마다 버스 하나(can0 · can1). 어느 팔이 어느 버스인지는 rig 기록이 가진다.
03

디스커버리와 장치 이름

#
방식설명
mDNS같은 네트워크 안에서 IP 를 몰라도 이름으로 서비스를 찾는 방식이다(멀티캐스트 DNS). 카메라 서버가 _pl-cam._tcp 로 자신을 광고하고, 구독자는 role 이름(top 등)으로 발견한다. IP 가 바뀌어도 설정을 고칠 필요가 없다.
DDS discoveryROS 노드끼리는 DDS 가 자동으로 서로를 찾는다. 단 네트워크 카드가 여러 개면 발견이 엉키므로, pl_supervisor 가 유선 NIC 하나로 고정한다(~/.ros/pl_cyclonedds.xml 생성).
장치 이름리더 어댑터는 udev 규칙이 /dev/openarm_leader_right 같은 고정 이름을 만든다. 카메라는 USB 물리 포트 경로로 구분한다 — 같은 모델 카메라는 시리얼이 겹칠 수 있어서다.
04

시간 동기화

#

한 에피소드의 관측은 두 보드의 시계로 찍힌다. 팔 상태(/joint_states)는 compute 보드가, 리더 상태와 프레임 조립은 leader 보드가 스탬프한다. 두 시계가 갈라지면 프레임 정렬이 조용히 틀어지는데, 이 결함은 데이터에서는 보이지 않다가 학습 결과에서야 드러난다. 그래서 이 프로젝트는 시계를 맞추는 것과 별개로, 안 맞으면 녹화를 시작하지 못하게 막는다.

단계설명
동기 — chrony (NTP)두 보드 모두 chrony 로 시계를 맞춘다. 기준 서버는 사이트 기록(config/sites/lab.yaml 의 chrony_server, 유선 IP)이 지정한다. 유선 네트워크의 정상 동기는 1 ms 미만이다.
점검 — netcheckpython -m tools.netcheck 가 chronyc tracking 오프셋을 검사한다(5 ms 이상이면 경고). NIC · DDS 도메인 · mDNS 와 함께 네트워크 일관성 점검의 일부다.
게이트 — start_episode 거부recorder 는 compute 보드가 스탬프한 /joint_states(100 Hz)의 "도착 시각 − 스탬프" 표본 median 을 상시 감시한다. 50 ms 를 넘거나 아예 측정되지 않으면 에피소드 시작을 거부한다 — 경고가 아니다.

50 ms 의 근거: 녹화가 30 Hz 이므로 프레임 주기가 33 ms 다 — 반 프레임을 넘는 시계 차이는 관측이 옆 프레임에 잘못 붙는 것과 같다. median 으로 판정하는 이유는, 단발 스파이크(디스커버리 · GC) 하나가 녹화를 막으면 운영자가 게이트를 믿지 않게 되기 때문이다. "측정 안 됨"도 거부하는 이유는 간단하다 — 모름은 0 이 아니다.

05

주요 용어

#
용어뜻
contract (계약)모듈이 외부에 공개하는 것(토픽·관절 그룹·QoS)을 적은 yaml 파일. 코드가 아니라 데이터다.
composition이 로봇이 어떤 모듈로 이루어지는지 적은 선언. robot/composition.yaml.
resolver계약 + 선언 + 설정을 읽어 파라미터·스키마를 생성하는 프로그램. 검증 실패면 기동을 거부한다.
schemaresolver 의 산출물(generated/schema.json). 수집·추론이 아는 유일한 로봇 정의.
rig물리적 로봇 한 대(개체). rig 기록은 그 개체의 실측값(캘리브·배선·카메라)이다.
lease · heartbeat팔 명령권. 한 번에 한 프로그램만 lease 를 갖고, heartbeat(0.2초 간격 생존 신호)가 끊기면 자동 반납된다.
intent명령 후보. 소스는 모터에 직접 명령하지 못하고 intent 를 발행하며, 안전 게이트가 통과 여부를 정한다.
fail-closed감시가 사라지면 자동으로 안전한 상태(정지)가 되는 설계. 반대는 fail-open.
URDF · xacro로봇 형상(링크·관절·한계)을 적는 ROS 표준 형식. xacro 는 그걸 매크로로 조립하는 도구.
MJCFMuJoCo 시뮬레이터의 모델 형식. 기구 값이 URDF 와 같아야 한다.
QoSDDS 토픽의 전달 정책(신뢰성·큐 깊이 등). 이 프로젝트에서는 계약이 선언한다.
ros2_controlROS 의 표준 제어 프레임워크. 컨트롤러와 하드웨어 드라이버(plugin)를 주기로 연결한다.
